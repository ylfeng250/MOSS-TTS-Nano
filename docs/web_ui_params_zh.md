# MOSS-TTS-Nano Web 界面参数说明

本文档详细说明 `app.py`（PyTorch 版）和 `app_onnx.py`（ONNX 版）Web 界面中各项参数的含义和调整方法。

---

## 一、基本参数

| 参数 | 默认值 | 说明 |
|---|---|---|
| **演示** | 第一个 Demo | 从下拉列表选择预置演示，自动填充参考音频和文本 |
| **参考音频** | Demo 音频 | 上传自定义参考音频（WAV/MP3/FLAC/M4A 等），用于语音克隆的音色模板 |
| **文本** | 空 | 输入想要合成的文本内容 |

---

## 二、生成选项

展开"生成选项"可调整以下高级参数。

### 2.1 帧与分块控制

| 参数 | 默认值 | 范围 | 说明 |
|---|---|---|---|
| **最大生成帧数** | 375 | 64 ~ 1024 | 每次生成的最大音频帧数。值越大，单次可合成的音频越长。通常无需调整 |
| **语音克隆最大文本 Token 数** | 75 | 25 ~ 200 | 长文本自动分块时，每块的最大 Token 数。较小值使分块更细，适合长文本合成 |
| **最大 TTS 批大小** | 1 | 0 或正整数 | 0 = 自动；1 = 强制分块逐一运行。增大可提高吞吐，但需更多显存 |
| **最大 Codec 批大小** | 0 | 0 或正整数 | 0 = 自动；控制音频解码的批大小。与 TTS 批大小配合使用 |

### 2.2 硬件与后端

| 参数 | 默认值 | 说明 |
|---|---|---|
| **CPU 线程数** | CPU 核心数 | 仅 CPU 模式有效，对应 `torch.set_num_threads`。ONNX 版选择对应缓存的运行时实例 |
| **注意力后端**（PyTorch）| model_default | `model_default`：模型默认；`sdpa`：缩放点积注意力（推荐 GPU）；`eager`：标准注意力（CPU 推荐） |
| **采样模式**（ONNX）| fixed | `fixed`：使用内置 ONNX 采样常量；`full`：使用页面上的超参数；`greedy`：禁用采样，使用贪心解码 |

### 2.3 采样参数

这些参数控制生成音频的多样性和稳定性，是调整合成效果最常用的参数。

| 参数 | 默认值 | 范围 | 说明 |
|---|---|---|---|
| **音频温度** | 0.8 | 0.1 ~ 2.0 | **最关键的参数之一**。越低越稳定可预测，越高越多样但可能出现异常。顿挫时可尝试降低到 0.6 |
| **音频 Top P** | 0.95 | 0.1 ~ 1.0 | 核采样阈值，控制候选 Token 的概率累积范围。降低可减少异常输出 |
| **音频 Top K** | 25 | 1 ~ 100 | 每步只从概率最高的 K 个 Token 中采样。降低使输出更保守 |
| **音频重复惩罚** | 1.2 | 1.0 ~ 2.0 | **解决顿挫最直接的参数**。增大（如 1.5~2.0）可有效减少重复和卡顿现象 |
| **文本温度** | 1.0 | 0.1 ~ 2.0 | 文本层的采样温度。通常无需调整 |
| **文本 Top P** | 1.0 | 0.1 ~ 1.0 | 文本层的核采样阈值。通常无需调整 |
| **文本 Top K** | 50 | 1 ~ 100 | 文本层的 Top-K 采样。通常无需调整 |
| **随机种子** | 0 | 任意整数 | 固定种子可复现生成结果。0 表示不固定 |
| **启用采样** | 勾选 | - | 取消勾选则使用贪心解码（确定性输出）。ONNX 版此选项由采样模式自动决定 |

### 2.4 文本处理

| 参数 | 默认值 | 说明 |
|---|---|---|
| **启用 WeTextProcessing** | 勾选 | 对输入文本进行规范化处理（数字转汉字、符号修正等），提升合成质量 |
| **启用 normalize_tts_text** | 勾选 | 额外的 TTS 文本规范化，与 WeTextProcessing 独立开关 |

### 2.5 流式播放

| 参数 | 默认值 | 说明 |
|---|---|---|
| **实时流式解码** | 勾选 | 边生成边播放音频，无需等待完整合成。取消勾选则为缓冲模式（全部生成后再播放） |
| **初始播放延迟（秒）** | 0.08 | 流式播放前等待的缓冲时间。增大可减少播放中断，但增加首音频延迟 |

## 三、常见调参建议

### 音频有顿挫或重复

1. 增大 **音频重复惩罚** → 1.5 或 2.0
2. 降低 **音频温度** → 0.6
3. 如文本较长，确保使用流式解码或 `--text-file` 自动分块

### 音频过于单调机械

1. 适当增大 **音频温度** → 1.0
2. 减小 **音频重复惩罚** → 1.0
3. 更换参考音频，选择语调更自然的录音

### 音色不像参考音频

1. 确保参考音频清晰、无噪声、自然流畅
2. 尝试不同时长的参考音频（5~10 秒最佳）
3. 参考音频与目标文本语言一致效果最佳

### 长文本合成质量差

1. 减小 **语音克隆最大文本 Token 数** → 50
2. 开启 **实时流式解码**
3. 适当增大 **初始播放延迟** → 0.15~0.20 秒

### 合成中途出现"深呼吸"声

长文本合成时，文本会被自动分块（chunk）逐段生成，每个 chunk 之间会出现明显的停顿，听起来像"深呼吸"。这是因为**两层停顿叠加**造成的：

1. **模型自身的自然停顿**：模型学到了人在句间会呼吸的规律，会在每个 chunk 末尾生成一段类似呼吸/停顿的音频，这是正常的
2. **代码插入的静音间隔**：系统在 chunk 之间还会额外插入 0.24~0.40 秒的纯静音（短文本 chunk 间隔 0.40 秒，长文本 chunk 间隔 0.24 秒），与模型的自然停顿叠加后总间隔偏长

**缓解方法**：

- 增大 **语音克隆最大文本 Token 数**（如 100~150），让更多文本在一个 chunk 内完成，减少分块数量
- 缩短单次合成的文本长度，减少自动分块
- 更换参考音频，避免使用本身带有明显呼吸声的录音（模型会捕捉并复现参考音频中的呼吸特征）

> 注：chunk 间的静音间隔时长目前为代码内置值，不在 Web 界面中直接可调。
